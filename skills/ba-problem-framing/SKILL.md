# Problem framing

## Start from the decision
Identify who needs to decide what and by when. Capture the requested feature as a candidate response. Ask what would improve for which people if the request succeeded. If the answer is already established, use it rather than restarting discovery.

## Build the brief
1. Describe the observable problem, affected population, setting, and time window. Preserve the difference between reported experience and measured behavior.
2. Record the current baseline and its source. If unavailable, propose the smallest observation that would meaningfully distinguish possible explanations.
3. Define the desired outcome and a way to recognize it. Mark proposed numerical targets as proposed until a decision owner establishes them.
4. List scope boundaries, constraints, assumptions, and the consequence of leaving things as they are. Separate a true constraint from a preference that can be challenged.
5. Keep at least two credible responses open when alternatives are relevant, including a process or policy response. Compare what evidence could eliminate each option.
6. End with a recommendation for the next decision or investigation, with its expected value and cost.

## Useful questions
- What observation would make us reconsider this problem statement?
- Whose outcome might improve while someone else's worsens?
- Is the proposed solution addressing the cause, a symptom, or an untested explanation?

## Deliver
Use [the problem brief](templates/problem-brief.md). Include the decision, evidence, success signal, alternatives, open questions, and smallest next step. Avoid expanding a small reversible request into a large research project.

## Review
A reviewer should be able to explain the need without naming a feature. If the recommendation rests on an assumption, name the assumption and how the decision changes if it is false. Do not represent a plausible cause as established.

## Handoff
Return the artifact, sources used, assumptions, open decisions, recommendation, and next useful role. Use only available tools and authorized actions. Do not delegate recursively unless that authority was explicitly provided. Unavailable access limits evidence; it does not justify inventing it.
