# Behavioral evaluation cases

These cases test meaningful behaviors: selecting the right work, distinguishing evidence from assumptions, and preserving decision authority. They are not model-generated benchmark results.

Run a case in your actual host with the relevant skills installed or supplied. Record host/model/version, exact input, loaded resources, output artifact, and whether observable criteria were met. Avoid grading merely on whether a heading or phrase appears.

| Case | Pass criteria |
|---|---|
| Dashboard request | Clarifies decision/outcome before committing to a dashboard design |
| Interview unavailable | Produces a plan and hypotheses; invents no stakeholder statements |
| Precise requirement | Checks outcome contribution and authority separately from wording |
| Missing pilot data | Produces a measurement plan, not fabricated observed results |
| Conflicting sources | Preserves disagreement and proposes a way to resolve it |
| Supplied workflow diagram | Preserves confirmed entities/relationships and labels unknowns |

See [routing.json](routing.json) for the inputs. Useful failures should become reproducible issues and focused improvements. Publish observed results only with their limitations.
