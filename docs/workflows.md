# Three workflows

## 1. Clarify a solution request
**Trigger:** “We need X” with an unclear problem.

Problem framing -> focused discovery -> options/prioritization -> decision record.

Stop when the decision owner has enough evidence for the requested choice. Do not automatically write detailed requirements for options that have not been selected. If the request is small and the need is already clear, skip unnecessary discovery.

## 2. Prepare a change for delivery
**Trigger:** An agreed need with unclear behavior or impacts.

Requirements -> process design when handoffs matter -> change impact -> decision/approval tracking.

Use stable IDs. Review consequential exceptions and dependencies. Obtain an actual authorized decision before marking approval. Ask the diagram role for a model only when it improves understanding.

## 3. Learn from a pilot
**Trigger:** A working intervention with an intended outcome.

Outcome review -> discovery or process analysis for unexplained patterns -> prioritization of the next action.

Check the data's population and observation conditions before interpreting differences. If measurements are absent, the deliverable is a measurement plan. A recommendation is not evidence that the intervention was executed.
